## Architecture decisions

Record each material change here or in a short ADR.
Each entry needs: behavior, existing packages, verified gap, selected approach, rejected approach, and test.

### Native runtime and host boundary

- **Behavior:** embeddable coding sessions, task control, effect ownership, durable context, and bounded work.
- **Existing packages:** Jido AgentServer/supervision, Jido.AI.Agent/ReAct, Jido signals/telemetry, Jido.Storage.File, Jido.Exec.
- **Gap:** workspace/permission identity, durable coding-specific effect intent, stable host event envelope, session admission, and host capability adapters.
- **Selected design:** host-supervised ordinary OTP runtime; a coding-specific session coordinator around real Jido agents; Jido Actions for tools; installed storage callbacks for persistence. Account secrets resolve per request and never enter durable session state.
- **Rejected:** custom model loop/transport/event bus/process framework; default global coding instance; TypeScript/Bun tool host.
- **Evidence:** dependency source inspected; public runtime and fault behavior tests are being written before broad implementation.
- **Operational impact:** names and quotas supplied by each host instance; no process-wide working-directory or environment mutation. External execution is capability-gated, not represented as an OS sandbox.

### Dependency integration and optional runtimes

- **Behavior:** runtime Actions, model transport, AST tooling, and optional three-language Eval.
- **Reuse:** installed ReqLLM/Jido Action installers, ExAST/Sourceror, QuickBEAM, Snakepit.
- **Gap/design:** declare direct dependencies only for imported runtime APIs; keep VibeKit/installer packages development-only and QuickBEAM/Snakepit optional with no automatic host runtime startup.
- **Installer evidence:** inspected actual installer sources; `mix igniter.install ... --yes --dry-run` added direct dependencies despite documented dry-run behavior (`artifact://27`, reported tool issue). Then `mix igniter.install jido_action@2.4 req_llm@1.28 --yes` applied actual Jido Action configuration (`artifact://29`). ExAST/Sourceror/Req/Zoi/Jason have no installers in installed source.
- **Safety:** Effect retries disabled. Eval and candidate workers use bounded JSON-only owned Ports, not OTP `:peer`: its standard-IO protocol accepts worker-controlled host messages. QuickBEAM remains JS Eval only; Snakepit remains Python Eval only. OS containment still belongs to the host. Python provisioning must not invoke an automatic installer.
